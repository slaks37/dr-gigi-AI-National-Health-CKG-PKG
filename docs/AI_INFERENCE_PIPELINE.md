# Image and inference pipeline

1. Validate authentication, bounded JSON envelope, symptoms and consent; perform emergency triage before image decoding.
2. Validate nonemergency subject linkage and request schema. Apply shared Firestore quotas and idempotency.
3. Verify declared MIME against file signature; enforce decoded-byte and pixel limits; decode/rotate with Sharp. Normalize to aspect-preserving JPEG and strip metadata.
4. For HEIC/HEIF, a bounded worker attempts local `heic-decode` conversion. Single frame, 12 megapixels, two live workers, ten-second worker deadline and heap limit apply. See [codec licenses](CODEC_LICENSES.md).
5. Assess dimensions, engineering brightness/blur indicators and exact duplicates. These thresholds are engineering safeguards, not clinically calibrated quality classifiers. Oral-region visibility cannot be inferred from pixel statistics.
6. Run a vision adapter only when model identity, version, validation evidence and approval reference are available. Per-attempt deadline, overall budget and abort signal bound work. The installed registry is empty, so no oral findings or confidence are generated by default.
7. Validate adapter findings; apply deterministic research rules. Save structured output and audit atomically. An emergency response may carry `persistence: FAILED`; clients must not report successful storage.

General object-detection backbones are candidate tools, not oral diagnostic models. No pretrained clinical weights or synthetic clinical performance claims are included. Optional LLM explanation must consume already validated structure, never revise triage, findings or codes; this implementation does not need an LLM.

Reference: [Torchvision model documentation](https://docs.pytorch.org/vision/stable/models.html). Weight licenses, clinical suitability and calibration need separate review before installation.
