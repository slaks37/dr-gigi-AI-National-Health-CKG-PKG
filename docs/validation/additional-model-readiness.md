## Source and artifact evidence

- Classifier: pinned [`app.py`](https://github.com/slaks37/Oral-Disease-detector-sonri/blob/9f96216e6daf5db71408285899a923b8fe0a59e3/app.py) and [`class_names.json`](https://github.com/slaks37/Oral-Disease-detector-sonri/blob/9f96216e6daf5db71408285899a923b8fe0a59e3/class_names.json). The exposed image function supplies raw float RGB. Static inspection now confirms internal Rescaling by 1/255, Normalization and a second channel-wise Rescaling; do not silently add external division by 255. A named preprocessing Lambda still needs explicit runtime review. There is no healthy/background class, and a softmax vector is not a calibrated disease probability. The author's reported random image split does not establish patient independence. Fresh [Kaggle model metadata](https://www.kaggle.com/api/v1/models/list?search=oral-disease-trained-model) identifies the [Keras/default model instance](https://www.kaggle.com/models/abdelhameednasr/oral-disease-trained-model/Keras/default). ## Worker acceptance before changing availability

Use separate TensorFlow classifier, DENTEX/Detectron2 panoramic, multistage panoramic, and nnU-Net CBCT runtimes when needed; importing them into the shared HTTP worker would mix incompatible dependencies and input contracts. Admission must bind source revision, runtime dependency/image digest, checkpoint SHA-256, model/data/code rights, label metadata, modality and preprocessing. Model loading is untrusted-code-sensitive; inspect archive paths, avoid arbitrary Python/pickle execution, and restrict access/network/resource use during artifact verification.

After artifact admission, run synthetic contract/negative tests and **real inference** separately. Report each model's runtime result, then use independent licensed annotations for the correct metric: detection AP/recall/false negatives and localization for DENTEX, image-level confusion and abstention for the classifier, masks/landmark/measurement errors for the bone-loss pipeline, and instance Dice/identity errors for CBCT. Audit patient/augmentation/volume overlap and obtain authorized clinician review. Neither catalog coverage nor an image-level classifier can be relabeled as per-tooth detection or disease confirmation.

No model training, paid compute, dataset access-account creation, TensorFlow runtime installation, clinical promotion or production deployment was initiated by this readiness inspection. Only an isolated private h5py/NumPy environment was installed for data-only artifact inspection; the existing inference runtime and registry were not changed.
